# 10 — PCB/SCH roadmap

## Current scope

TwinStudio now includes the reusable `twinstudio.kicad_dsl` adapter and the
`twinstudio.eda/v1` intermediate representation. It parses native
`.kicad_sch` and `.kicad_pcb` S-expressions, preserves unknown syntax during
targeted edits, and addresses placed objects by native UUID and reference.

The first allow-list intentionally stays small:

- schematic: update an existing symbol `Value` or `Footprint` property;
- PCB: move an existing footprint to an absolute X/Y/rotation;
- both: reject stale source hashes, ambiguous targets, path traversal and
  unsupported operations;
- apply: create an immutable candidate plus `change.json`; never overwrite the
  source file.

Connectivity editing, symbol placement, track/zone/outline edits, synthesis
and autorouting are not implemented in v1.

## Selection model for PCB/SCH

A PCB/SCH selection should use stable native UUIDs, not screen pixels alone:

- sheet/symbol/pin/net UUID;
- footprint/pad/track/via/zone UUID;
- board outline segment;
- rule/constraint object;
- screenshot region as supplementary evidence.

The same `RegionSelection → SelectionMap → ChangePlan` flow applies, with operations such as set property, replace symbol, move footprint, edit outline, add keep-out or route a constrained net.

## Safety rules

- LLM emits typed operations only.
- Adapter checks base revision and selected UUID scope.
- No arbitrary script generated by the model is executed.
- Every accepted change creates a review candidate and must pass renderer
  export; ERC/DRC automation remains a required gate before source promotion.
- Netlist/footprint/library changes receive explicit impact analysis.
- Manufacturing outputs are regenerated and hashed.

## Included adapter scaffold

`examples/rpi5-camera3/pcb/kicad_adapter.py` discovers `kicad-cli` and orchestrates explicit ERC/DRC/export commands for supplied native files. It does not create a circuit or autoroute.

The scaffold remains a CLI-check boundary. Native parsing and controlled
writing live in `src/twinstudio/kicad_dsl.py`, so Viewer and Wiki do not copy
the adapter.

## REST workflow

- `GET /api/v1/eda/sch2dsl?path=...`
- `GET /api/v1/eda/pcb2dsl?path=...`
- `POST /api/v1/eda/nl2dsl`
- `POST /api/v1/eda/dsl2sch` and `POST /api/v1/eda/dsl2pcb`

`nl2dsl` uses the existing strict LiteLLM JSON-Schema path when
`LITELLM_MODEL` is configured. Otherwise it uses the deterministic local
compiler with the identical output schema. The source root is allow-listed by
`TWINSTUDIO_KICAD_ROOT`; candidates are stored below
`TWINSTUDIO_DATA_DIR/artifacts/kicad-edits`.

Artifact Viewer owns the editing UI and KiCad preview/export only. Maskservice
Wiki owns discovery and links to Viewer. Neither service writes the source.

## Roadmap

1. Extend the IR with pins, pads, nets and connectivity graph.
2. Map KiCanvas selections to UUIDs and POA URIs.
3. Add automatic ERC/DRC and semantic before/after diff gates.
4. Promote an approved candidate through CQRS/event history into a chosen
   source branch.
5. Add interface contracts between PCB, enclosure and purchased components.
6. Add electrical simulation and test-point plans.
7. Add fabrication/assembly quotation and lifecycle approval.
