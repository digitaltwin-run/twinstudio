# 10 — PCB/SCH roadmap

## Current scope

TwinStudio now includes the reusable `twinstudio.kicad_dsl` adapter and the
`twinstudio.eda/v1` intermediate representation. It parses native
`.kicad_sch` and `.kicad_pcb` S-expressions, preserves unknown syntax during
targeted edits, and addresses placed objects by native UUID and reference.

The first allow-list intentionally stays small:

- schematic: update an existing symbol `Value` or `Footprint` property;
- PCB: move an existing footprint to an absolute X/Y/rotation;
- both: reject stale source hashes, ambiguous targets, path traversal and
  unsupported operations;
- apply: create an immutable candidate plus `change.json`; never overwrite the
  source file.

Connectivity editing, symbol placement, track/zone/outline edits, synthesis
and autorouting are not implemented in v1.

## Selection model for PCB/SCH

A PCB/SCH selection should use stable native UUIDs, not screen pixels alone:

- sheet/symbol/pin/net UUID;
- footprint/pad/track/via/zone UUID;
- board outline segment;
- rule/constraint object;
- screenshot region as supplementary evidence.

The same `RegionSelection → SelectionMap → ChangePlan` flow applies, with operations such as set property, replace symbol, move footprint, edit outline, add keep-out or route a constrained net.

## Safety rules

- LLM emits typed operations only.
- Adapter checks base revision and selected UUID scope.
- No arbitrary script generated by the model is executed.
- Every accepted change creates a review candidate and must pass renderer
  export; ERC/DRC automation remains a required gate before source promotion.
- Netlist/footprint/library changes receive explicit impact analysis.
- Manufacturing outputs are regenerated and hashed.

## Included adapter scaffold

`examples/rpi5-camera3/pcb/kicad_adapter.py` discovers `kicad-cli` and orchestrates explicit ERC/DRC/export commands for supplied native files. It does not create a circuit or autoroute.

The scaffold remains a CLI-check boundary. Native parsing and controlled
writing live in `src/twinstudio/kicad_dsl.py`, so Viewer and Wiki do not copy
the adapter.

## REST workflow

- `GET /api/v1/eda/sch2dsl?path=...`
- `GET /api/v1/eda/pcb2dsl?path=...`
- `POST /api/v1/eda/nl2dsl`
- `POST /api/v1/eda/dsl2sch` and `POST /api/v1/eda/dsl2pcb`

`nl2dsl` resolves the central SubLLM route `twinstudio/eda-nl2dsl`. The current
route prefers direct Z.AI GLM 5.3 and falls back only to the allow-listed
OpenRouter GLM 5.2 transport. Providers with native JSON Schema support receive
the schema as `response_format`; Z.AI receives it in the request document.
Every response is still validated locally with the full Pydantic schema,
immutable source identity and UUID/reference scope. If SubLLM or its provider
is unavailable, the deterministic local compiler produces the identical DSL
and reports an explicit `local-fallback` mode. The source root is allow-listed by
`TWINSTUDIO_KICAD_ROOT`; candidates are stored below
`TWINSTUDIO_EDA_CANDIDATES_ROOT` (by default
`TWINSTUDIO_DATA_DIR/artifacts/kicad-edits`). Point it at a shared project
candidate directory when TwinStudio and its Viewer run as separate services.

The `twinstudio eda` CLI exposes the same adapter without an HTTP server:
`inspect`, `plan`, `check`, `apply`, and an interactive `shell`. `apply` always
writes a versioned candidate. `audit-firmware` uses the separately pinned
SubLLM route `twinstudio/eda-firmware-audit` (Z.AI GLM 5.3) to review a
deterministic comparison of `board.GP<n>` firmware use with explicit `GP/GPIO`
schematic labels. It never claims that unlabeled wires are verified; use ERC or
a KiCad netlist for that electrical proof. The PCB writer also supports a
bounded `assign_pad_net` operation: it resolves one footprint and one pad,
reuses an existing named net or explicitly creates a requested one, and always
writes a versioned candidate. It does not route copper, so DRC and routing remain
required after a connectivity change.

Shared KiCad parsing, inspection and routing geometry live in the independently
versioned `twin-kicad` package. Its bounded multi-net and fail-closed maze
routers never narrow a declared track to gain reachability and emit only
rectilinear segments with explicit via dimensions. It is a geometry primitive,
not an approval bypass: a result with any unrouted net is diagnostic only,
while a complete result still needs connectivity comparison, KiCad DRC and
explicit candidate acceptance before promotion.

TwinStudio owns the canonical EDA event stream and content-addressed revisions.
Artifact Viewer owns editing, rendered comparison and explicit decisions. Wiki
only reads the TwinStudio timeline and links to revisions. Promotion is the only
operation that replaces the current source; it is hash-bound, requires an
accepted candidate and preserves both versions by SHA-256. Revert has the same
optimistic hash guard. Migration imports legacy sidecars without changing KiCad
sources.

Project routes use `/api/v1/projects/{project_id}/eda/...` for plan, apply,
history, accept, reject, promote, revert and migration. Portable project state
is written as `project.twinstudio.json`, `.twinstudio/event-stream.ndjson` and
`.twinstudio/logs/eda.jsonl`; `change.json` remains a transferable candidate
manifest, not an approval store.

## Roadmap

1. Extend the pad/net IR into a full schematic pin and connectivity graph.
2. Map KiCanvas selections to UUIDs and POA URIs.
3. Extend the implemented DRC and semantic before/after gates with ERC.
4. Integrate promotion with chosen Git branches in addition to the implemented
   local atomic source promotion.
5. Add interface contracts between PCB, enclosure and purchased components.
6. Add electrical simulation and test-point plans.
7. Add fabrication/assembly quotation and lifecycle approval.
